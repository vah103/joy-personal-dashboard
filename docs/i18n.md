# Joy UI language rules

Joy uses one shared interface-language system: `src/i18n`.

## Rules

1. New UI copy must use `window.JoyI18n.t("semantic.key")` or `data-i18n="semantic.key"`.
2. Every key must exist in both `src/i18n/locales/en.js` and `src/i18n/locales/vi.js`.
3. Feature modules must not create their own English/Vietnamese dictionaries or DOM translation layers. Legacy adapters may only delegate to `JoyI18n` until removed.
4. User data is not UI copy. Names, addresses, notes, tasks, project content, email content and source listings must stay unchanged.
5. Input/parser language is independent from interface language. Vietnamese natural-language inputs such as `mai 8h tối` continue to work when the interface is English.
6. Feature-specific content transformations are separate from UI language. For example `task-english.js` can rewrite a task because that is a task feature, not interface localization.
7. Dates, numbers and currency shown as UI should use `JoyI18n.formatDate`, `formatNumber` or `formatCurrency` when new code is added.

## Adding copy

```js
button.textContent = window.JoyI18n.t("sales.createAppointment");
```

Add the same semantic key to both locale files. Do not add a new `*-english-ui.js`, `*-vietnamese-ui.js` or per-feature translation map.

## Settings

The selected interface language is stored under `joy-ui-language-v1` in `localStorage` and shared across dashboard, login and Sale workspace on the same origin. English is the fallback for existing users with no saved preference.

## CI

`npm run i18n:check` verifies locale-key parity, placeholder parity, referenced literal keys and that the remaining legacy language adapters delegate to the shared engine.
